Removing protection from all sheets at once

What sheet and workbook protection actually does, and how to unprotect many sheets quickly.

You receive a workbook with twenty protected sheets and need to change something. Clicking Review → Unprotect Sheet on each one is tedious, and when nobody remembers the password it stops there.

What kinds of protection exist

  • Sheet protection blocks editing of locked cells, formatting, inserting rows and so on. It is a convenience feature, not security: the password is stored in the file in a form that can be bypassed.
  • Workbook structure protection prevents adding, deleting, renaming and moving sheets.
  • VBA project protection locks the macro code view.
  • File encryption (File → Info → Protect Workbook → Encrypt with Password) is the only one that is real security. Without the password the file cannot be opened.

When you know the password

Unprotecting each sheet by hand works but is slow. A short macro loops through sheets:

Sub UnprotectAll()
    Dim ws As Worksheet
    For Each ws In ActiveWorkbook.Worksheets
        ws.Unprotect "password"
    Next
End Sub

If the passwords differ between sheets, this will raise an error on the first mismatch, so wrap it in error handling.

When you do not

First, ask the author. If the file belongs to you or your company and the author is gone, the protection can be removed because sheet protection is not encryption. An .xlsx file is a ZIP archive; renaming it to .zip and deleting the <sheetProtection> element from xl/worksheets/sheetN.xml removes the protection from that sheet. It works but takes several steps per sheet and is easy to get wrong.

Only do this with files you have the right to edit.

With the add-in

Unprotect Workbook removes protection from all worksheets, the workbook structure and the VBA project in one command, and no password is required. It does not work with encrypted workbooks, because that password is needed to open the file in the first place.

A note on protecting your own files

If you protect a sheet to prevent accidental edits, sheet protection is enough. If the data is confidential, use file encryption or do not send the file at all.

Снятие защиты со всех листов сразу

Что на самом деле защищают защита листа и книги и как быстро снять защиту со многих листов.

Вам прислали книгу с двадцатью защищёнными листами, и нужно что-то изменить. Нажимать Рецензирование → Снять защиту листа на каждом долго, а если никто не помнит пароль, дело на этом и встаёт.

Какие бывают виды защиты

  • Защита листа запрещает редактировать заблокированные ячейки, менять формат, вставлять строки и так далее. Это удобство, а не безопасность: пароль хранится в файле в виде, который можно обойти.
  • Защита структуры книги не даёт добавлять, удалять, переименовывать и перемещать листы.
  • Защита VBA-проекта закрывает просмотр кода макросов.
  • Шифрование файла (Файл → Сведения → Защита книги → Зашифровать с использованием пароля) – единственный вариант настоящей защиты. Без пароля файл не открыть.

Если пароль известен

Снимать защиту с каждого листа вручную можно, но долго. Короткий макрос обходит листы в цикле:

Sub UnprotectAll()
    Dim ws As Worksheet
    For Each ws In ActiveWorkbook.Worksheets
        ws.Unprotect "password"
    Next
End Sub

Если пароли на листах разные, на первом несовпадении возникнет ошибка, поэтому добавьте обработку ошибок.

Если пароля нет

Сначала спросите автора. Если файл ваш или принадлежит вашей компании, а автор недоступен, защиту можно снять, потому что защита листа не является шифрованием. Файл .xlsx – это ZIP-архив; если переименовать его в .zip и удалить элемент <sheetProtection> из xl/worksheets/sheetN.xml, защита с этого листа будет снята. Это работает, но требует нескольких шагов на каждый лист, и легко ошибиться.

Делайте это только с файлами, которые вы вправе изменять.

С надстройкой

Команда Снять защиту книги (Unprotect Workbook) одним действием убирает защиту со всех листов, структуры книги и VBA-проекта, пароль не нужен. С зашифрованными книгами она не работает, так как пароль нужен уже для открытия файла.

Заметка про защиту собственных файлов

Если вы защищаете лист от случайных правок, защиты листа достаточно. Если данные конфиденциальны, используйте шифрование файла или вообще не отправляйте его.
