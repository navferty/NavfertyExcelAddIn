Preparing Excel files for import into 1C, Power BI and SQL

What import tools expect from a spreadsheet and how to get the file into that shape.

Import tools are strict where people are forgiving. A human reads a title, a merged header and a total row and understands the table. A loader sees a mess. Most import failures come down to the same few things.

Shape of the table

  • One header row, directly above the data. No title block above it, or know how many rows to skip.
  • No merged cells. Fill the repeated values instead.
  • No subtotal or grand total rows inside the data.
  • No blank rows or columns in the middle.
  • One table per sheet.

Column names

  • Unique, non-empty, short. Duplicated names get suffixes or cause an error.
  • For SQL, avoid spaces, punctuation and a leading digit. order_date is easier to work with than Order date (UTC).
  • Do not rename columns between exports. Many loaders map by name.

Types

  • Every column has one type. A single - or n/a in a numeric column turns the entire column to text in Power Query or in an automatic type detection.
  • Numbers are real numbers, not text with spaces. Dates are real dates. See text numbers and extra spaces.
  • Identifiers with leading zeros (codes, postal codes, phone numbers) are text, and stay text.
  • Keep the decimal separator consistent with the locale of the target system, or use an unambiguous format.
  • Use ISO dates (2024-03-12) in anything that goes to a database. Day/month order is the most common source of silent errors.

Values

  • Formulas are fine in Excel but some importers read the cached value, and a few read the formula text. If in doubt, paste the values into a clean sheet.
  • Remove leading and trailing spaces and non-breaking spaces from keys.
  • Check for error values (#N/A, #REF!) before the import: a loader may stop or load them as text. See finding errors.
  • For XML-based imports, make sure text has no characters that are illegal in XML.

Tool-specific notes

Power BI / Power Query. Prefer an Excel table (Ctrl+T) or a named range as the source: it keeps working when rows are added. Rename columns in the source rather than in the query when you can.

SQL. CSV with UTF-8 is the least troublesome format (see CSV and encoding). For SQLite, an export straight from the workbook is an option.

1C. Typical import processing expects a fixed column order and a single header row. Check the required template for the document type, and verify tax IDs, codes and dates before the load. A wrong TIN or a text date is rejected row by row, which is slow to fix after the fact.

A dry run

Import ten rows first. It is much faster to diagnose a problem on ten rows than on fifty thousand.

Подготовка файлов Excel к импорту в 1С, Power BI и SQL

Что инструменты импорта ждут от таблицы и как привести файл в нужный вид.

Инструменты импорта строги там, где люди снисходительны. Человек видит заголовок, объединённую шапку и строку итогов и понимает таблицу. Загрузчик видит кашу. Большинство сбоев импорта сводится к нескольким одинаковым причинам.

Форма таблицы

  • Одна строка заголовков непосредственно над данными. Над ней нет блока заголовка, либо вы знаете, сколько строк пропустить.
  • Без объединённых ячеек. Заполните повторяющиеся значения.
  • Без строк промежуточных и общих итогов внутри данных.
  • Без пустых строк и столбцов посередине.
  • Одна таблица на лист.

Названия столбцов

  • Уникальные, непустые, короткие. Одинаковые названия получают суффиксы или вызывают ошибку.
  • Для SQL избегайте пробелов, знаков препинания и цифры в начале. С order_date проще работать, чем с Дата заказа (UTC).
  • Не переименовывайте столбцы от выгрузки к выгрузке. Многие загрузчики сопоставляют по именам.

Типы

  • У каждого столбца один тип. Единственный - или «н/д» в числовом столбце превращает весь столбец в текст в Power Query или при автоопределении типов.
  • Числа – настоящие числа, а не текст с пробелами. Даты – настоящие даты. См. числа-как-текст и лишние пробелы.
  • Идентификаторы с ведущими нулями (коды, индексы, телефоны) – текст, и текстом остаются.
  • Десятичный разделитель должен соответствовать локали целевой системы, либо используйте однозначный формат.
  • Для всего, что идёт в базу данных, используйте даты в формате ISO (2024-03-12). Порядок «день/месяц» – самый частый источник тихих ошибок.

Значения

  • Формулы в Excel – это нормально, но некоторые загрузчики читают кэшированное значение, а некоторые – текст формулы. Если сомневаетесь, вставьте значения на чистый лист.
  • Уберите пробелы в начале и конце и неразрывные пробелы из ключей.
  • Перед импортом проверьте наличие ошибок (#Н/Д, #ССЫЛКА!): загрузчик может остановиться или загрузить их как текст. См. поиск ошибок.
  • Для импорта через XML убедитесь, что в тексте нет недопустимых в XML символов.

Особенности инструментов

Power BI / Power Query. В качестве источника лучше использовать таблицу Excel (Ctrl+T) или именованный диапазон: он продолжит работать при добавлении строк. По возможности переименовывайте столбцы в источнике, а не в запросе.

SQL. Меньше всего проблем создаёт CSV в UTF-8 (см. CSV и кодировки). Для SQLite есть вариант экспорта прямо из книги.

1С. Типовые обработки загрузки ожидают фиксированный порядок столбцов и одну строку заголовков. Проверьте требуемый шаблон для вида документа, а также ИНН, коды и даты перед загрузкой. Неверный ИНН или дата-как-текст отклоняются построчно, и исправлять это после загрузки долго.

Пробный прогон

Сначала загрузите десять строк. Разобрать проблему на десяти строках гораздо быстрее, чем на пятидесяти тысячах.
