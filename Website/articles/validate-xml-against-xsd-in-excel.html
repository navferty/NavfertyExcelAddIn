Validating XML against XSD inside Excel

How to check an XML file against its schema and read the errors as a table.

Many systems exchange data as XML: tax and customs declarations, bank statements, e-invoicing, product feeds. Often the XML is produced from an Excel table by a script or a conversion tool, and the receiving system rejects it with a message like “file does not conform to schema” without saying where the mistake is.

What an XSD is

An XSD (XML Schema) file describes which elements are allowed, in what order, which are required and what type each value has. Validating means checking an XML file against those rules. A file can be well-formed (correct tags) and still invalid (a required element is missing, or a text value sits in a date field).

Typical problems

  • A required element is missing or in the wrong order. Order matters in xs:sequence.
  • A value does not match its type: -5 for a positiveInteger, 12.03.2024 for an xs:date that expects 2024-03-12.
  • Decimal comma instead of a point.
  • Strings longer than maxLength or not matching a pattern (for example a tax ID of the wrong length).
  • Characters like < and & that were not escaped when the XML was written.

Other ways to validate

  • xmllint --noout --schema schema.xsd file.xml on Linux or macOS, and available for Windows too.
  • Editors with schema support, such as Visual Studio Code with an XML extension, Oxygen or Notepad++ with the XML Tools plugin.
  • Excel's own XML Maps (Developer → Source) can import an XSD and map it to cells. It is limited with nested or repeating structures.

With the add-in

Validate XML with XSD takes an XML file and an XSD file and writes a new workbook with one row per problem: severity, element and the message. Because it is a normal sheet, you can filter, sort and send it to the person who produced the data.

When you only have the schema and need to understand what a valid file looks like, Create Sample XML based on XSD generates an example file from it. For checks before the XML is even created, Validate Values checks that the cells hold numbers, dates, valid tax IDs, or text without characters that break XML.

Reading the messages

Messages mention the element name and the expected alternatives. Fix the first error first: later messages are often consequences of the first one, for example a missing element makes everything after it look out of order.

Проверка XML по XSD-схеме в Excel

Как проверить XML-файл на соответствие схеме и прочитать ошибки в виде таблицы.

Многие системы обмениваются данными в XML: налоговая и таможенная отчётность, банковские выписки, электронные счета, товарные фиды. Часто XML формируется из таблицы Excel скриптом или конвертером, а принимающая система отклоняет его с сообщением вроде «файл не соответствует схеме», не указывая, где ошибка.

Что такое XSD

XSD (XML Schema) описывает, какие элементы допустимы, в каком порядке, какие обязательны и какой тип у каждого значения. Валидация – проверка XML-файла по этим правилам. Файл может быть well-formed (теги записаны верно) и всё равно невалидным (пропущен обязательный элемент или в поле даты стоит текст).

Типичные проблемы

  • Обязательный элемент отсутствует или стоит не на своём месте. В xs:sequence порядок важен.
  • Значение не соответствует типу: -5 для positiveInteger, 12.03.2024 там, где xs:date ожидает 2024-03-12.
  • Десятичная запятая вместо точки.
  • Строки длиннее maxLength или не подходящие под pattern (например, ИНН неверной длины).
  • Символы < и &, не экранированные при записи XML.

Другие способы проверки

  • xmllint --noout --schema schema.xsd file.xml на Linux и macOS, доступно и для Windows.
  • Редакторы с поддержкой схем: Visual Studio Code с XML-расширением, Oxygen или Notepad++ с плагином XML Tools.
  • Собственные карты XML в Excel (Разработчик → Источник) умеют импортировать XSD и сопоставлять его с ячейками. Для вложенных и повторяющихся структур возможности ограничены.

С надстройкой

Команда Проверить XML по XSD (Validate XML with XSD) принимает XML-файл и XSD-файл и создаёт новую книгу, где одна строка соответствует одной проблеме: серьёзность, элемент и сообщение. Это обычный лист, его можно отфильтровать, отсортировать и отправить тому, кто подготовил данные.

Если у вас есть только схема и нужно понять, как выглядит корректный файл, команда Создать пример XML по XSD сформирует образец. А для проверок до создания XML есть Проверка значений: она проверяет, что в ячейках числа, даты, корректные ИНН или текст без символов, ломающих XML.

Как читать сообщения

В сообщениях указаны имя элемента и ожидаемые варианты. Исправляйте сначала первую ошибку: следующие часто являются её следствием, например пропущенный элемент делает всё после него «не в порядке».
