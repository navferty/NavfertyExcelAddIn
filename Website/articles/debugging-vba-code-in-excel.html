VBA debugging techniques in Excel (Russian)

Practical ways to find bugs in VBA code, with examples from Excel. Original article in Russian.

A macro that fails with “Run-time error 1004” does not say much on its own. The VBA editor has all the tools needed to find out why.

The author's article in Russian collects debugging techniques with Excel examples:

Techniques for debugging VBA code using MS Excel as an example (Pikabu, Russian)

A quick overview

  • Option Explicit at the top of each module turns a typo in a variable name into a compile error.
  • Breakpoints (F9) and stepping (F8 step into, Shift+F8 step over) let you watch the code run line by line.
  • Locals and Watch windows show the values of variables. A watch can break the execution when a condition becomes true.
  • Immediate window (Ctrl+G) evaluates expressions and runs procedures. Debug.Print writes to it.
  • Run to Cursor and Set Next Statement let you skip or repeat code while debugging.
  • Error handling with On Error GoTo, and Err.Number and Err.Description in the handler, so that the macro reports the real reason.
  • Turn off Application.ScreenUpdating and set calculation to manual in production code, and make sure they are restored on any exit path, including errors.
