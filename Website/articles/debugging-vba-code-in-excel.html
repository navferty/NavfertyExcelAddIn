VBA debugging techniques in Excel (Russian)

Practical ways to find bugs in VBA code, with examples from Excel. Original article in Russian.

A macro that fails with “Run-time error 1004” does not say much on its own. The VBA editor has all the tools needed to find out why.

The author's article in Russian collects debugging techniques with Excel examples:

Techniques for debugging VBA code using MS Excel as an example (Pikabu, Russian)

A quick overview

  • Option Explicit at the top of each module turns a typo in a variable name into a compile error.
  • Breakpoints (F9) and stepping (F8 step into, Shift+F8 step over) let you watch the code run line by line.
  • Locals and Watch windows show the values of variables. A watch can break the execution when a condition becomes true.
  • Immediate window (Ctrl+G) evaluates expressions and runs procedures. Debug.Print writes to it.
  • Run to Cursor and Set Next Statement let you skip or repeat code while debugging.
  • Error handling with On Error GoTo, and Err.Number and Err.Description in the handler, so that the macro reports the real reason.
  • Turn off Application.ScreenUpdating and set calculation to manual in production code, and make sure they are restored on any exit path, including errors.

Приёмы отладки VBA-кода на примере MS Excel

Практические способы найти ошибки в VBA-коде на примерах из Excel.

Макрос, который падает с «Run-time error 1004», сам по себе мало что объясняет. В редакторе VBA есть всё необходимое, чтобы выяснить причину.

Статья автора на Pikabu собирает приёмы отладки с примерами из Excel:

Приёмы отладки VBA-кода на примере MS Excel (Pikabu)

Краткий обзор

  • Option Explicit в начале каждого модуля превращает опечатку в имени переменной в ошибку компиляции.
  • Точки останова (F9) и пошаговое выполнение (F8 – с заходом, Shift+F8 – с обходом) позволяют смотреть, как код выполняется построчно.
  • Окна Locals и Watch показывают значения переменных. Наблюдение может остановить выполнение, когда условие станет истинным.
  • Окно Immediate (Ctrl+G) вычисляет выражения и запускает процедуры. Debug.Print пишет в него.
  • Run to Cursor и Set Next Statement позволяют пропустить или повторить код при отладке.
  • Обработка ошибок через On Error GoTo и Err.Number с Err.Description в обработчике, чтобы макрос сообщал реальную причину.
  • В рабочем коде отключайте Application.ScreenUpdating и ставьте ручной расчёт, но следите, чтобы они восстанавливались при любом выходе, в том числе при ошибке.
