Working with CSV files without encoding issues

Why Cyrillic and accented characters turn into garbage and how to open and save CSV correctly.

You open a CSV in Excel and see РџСЂРёРІРµС‚ instead of the expected text, or Ã© in place of é. The file is fine. Excel has simply guessed the wrong encoding.

What is happening

A CSV file is plain text, and nothing in it says which encoding is used. Double-clicking a file makes Excel use the system's legacy code page (for example Windows-1251 on Russian Windows, Windows-1252 on Western European systems), unless the file starts with a UTF-8 byte-order mark (BOM). A UTF-8 file without a BOM is therefore misread.

Opening a file correctly

  1. Do not double-click. Open a blank workbook.
  2. Data → From Text/CSV.
  3. Select the file. In the preview, change File Origin until the text looks right (usually 65001: Unicode (UTF-8), or 1251: Cyrillic (Windows) for older Russian files).
  4. Check the delimiter, then click Load or Transform Data.

Saving a file correctly

  • CSV UTF-8 (Comma delimited) in the Save As type list writes UTF-8 with a BOM. It is the one to choose when the file goes to another program or when it opens in Excel on another computer.
  • The plain CSV (Comma delimited) option saves in the system code page and loses characters that are not part of it.
  • Some strict importers reject the BOM. Then remove it with a text editor such as Notepad++ (Encoding → UTF-8) or save from there.

Delimiter problems

In many European locales, including Russian and German, Excel uses a semicolon as the list separator, since the comma is the decimal separator. A comma-separated file opened by double-click will land in one column, and a semicolon-separated file opened on an English system will do the same. In the From Text/CSV dialog, set the delimiter explicitly. In a text file, an sep=; line at the top forces Excel to use a semicolon, but other tools will see it as data, so use that only for files meant for Excel.

Other traps

  • Leading zeros disappear when Excel guesses the column as a number. In the import dialog, set the column type to Text.
  • Long numbers (more than 15 digits) are rounded and shown in scientific notation. Import them as text.
  • Dates are converted with the local day/month order. 03/04/2024 may mean the third of April or the fourth of March.
  • Fields with line breaks or delimiters must be in quotes, and quotes inside doubled. Programs that write CSV by concatenating strings often miss this.
  • Saving a CSV over and over in Excel changes the content (numbers, dates, zeros). Keep the original and the working .xlsx separate.

For recurring files

Use Power Query: it remembers the encoding, delimiter and column types, so the next file is a refresh away.

Работа с CSV-файлами без проблем с кодировкой

Почему кириллица и символы с диакритикой превращаются в «кракозябры» и как правильно открывать и сохранять CSV.

Вы открываете CSV в Excel и видите РџСЂРёРІРµС‚ вместо нормального текста, или Ã© вместо é. С файлом всё в порядке. Excel просто угадал не ту кодировку.

Что происходит

CSV – это обычный текст, и в нём ничего не сказано о кодировке. При двойном щелчке по файлу Excel использует системную кодовую страницу (например, Windows-1251 на русской Windows, Windows-1252 на западноевропейских системах), если только файл не начинается с метки порядка байтов UTF-8 (BOM). Поэтому файл в UTF-8 без BOM читается неверно.

Как правильно открыть файл

  1. Не открывайте двойным щелчком. Откройте пустую книгу.
  2. Данные → Из текстового/CSV-файла.
  3. Выберите файл. В окне предпросмотра меняйте Источник файла, пока текст не станет читаемым (обычно 65001: Юникод (UTF-8), а для старых русских файлов 1251: кириллица (Windows)).
  4. Проверьте разделитель, затем нажмите Загрузить или Преобразовать данные.

Как правильно сохранить файл

  • CSV UTF-8 (разделитель – запятая) в списке типов файлов записывает UTF-8 с BOM. Выбирайте его, когда файл идёт в другую программу или открывается в Excel на другом компьютере.
  • Обычный вариант CSV (разделители – запятые) сохраняет в системной кодовой странице и теряет символы, которых в ней нет.
  • Некоторые строгие загрузчики отвергают BOM. Тогда уберите его в текстовом редакторе, например в Notepad++ (Кодировки → UTF-8), и сохраните оттуда.

Проблемы с разделителем

Во многих локалях, включая русскую и немецкую, Excel использует в качестве разделителя списка точку с запятой, потому что запятая – десятичный разделитель. Файл с запятыми, открытый двойным щелчком, окажется в одном столбце, и то же случится с файлом с точкой с запятой на английской системе. В диалоге «Из текстового/CSV-файла» задайте разделитель явно. В текстовом файле строка sep=; в начале заставляет Excel использовать точку с запятой, но другие программы воспримут её как данные, поэтому применяйте только для файлов, предназначенных для Excel.

Другие ловушки

  • Ведущие нули пропадают, когда Excel угадывает столбец как число. В диалоге импорта задайте тип столбца «Текст».
  • Длинные числа (больше 15 цифр) округляются и показываются в экспоненциальной записи. Импортируйте их как текст.
  • Даты преобразуются с локальным порядком дня и месяца. 03/04/2024 может означать третье апреля или четвёртое марта.
  • Поля с переносами строк или разделителями должны быть в кавычках, а кавычки внутри удваиваться. Программы, записывающие CSV склейкой строк, часто это упускают.
  • Многократное пересохранение CSV в Excel меняет содержимое (числа, даты, нули). Храните оригинал и рабочий .xlsx отдельно.

Для регулярных файлов

Используйте Power Query: он запоминает кодировку, разделитель и типы столбцов, так что следующий файл – это одно обновление.
